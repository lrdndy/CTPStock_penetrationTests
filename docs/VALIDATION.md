# 第一阶段交付验证记录

本次验证检查应用代码的正确性和 SDK 配套情况。没有在本环境执行 Windows 原生编译、加载原生 DLL、连接中信服务器、认证或登录测试。正式实机结果仍为待执行。

## 已完成

- 原始 Windows 64 位 SDK 的 10 个文件与用户压缩包内对应文件逐字节一致。
- 编译使用的 4 个 UTF-8 头文件副本与原始 GBK 头文件解码后的文本一致，未改变字段和声明。
- `src/main.cpp` 使用实际接口头文件通过 Linux g++ C++17 语法检查；这不等于 MSVC 链接成功。
- 使用按实际头文件实现的离线假后端验证 20 个应用逻辑场景，全部符合预期。假后端不建立网络连接，不使用实际账号密码，并将未预期的 API 调用判为失败。
- 最终源码在上述离线测试中通过 AddressSanitizer 与 UndefinedBehaviorSanitizer 检查。容器限制下未启用 LeakSanitizer，不能据此宣称已证明无内存泄漏。
- 人工核对 Windows 构建、运行与打包脚本路径及参数；本环境没有 Windows / PowerShell，脚本仍需本机执行验证。

## 离线应用逻辑覆盖

| 场景组 | 实际检查 |
| --- | --- |
| 正常路径 | 交易与行情按顺序完成，结果各自汇总 |
| 认证 | 业务失败、提交失败、错误编号、错误编号后正确响应、必需响应为空 |
| 登录 | 业务失败、错误编号、认证旧响应在登录阶段迟到、必需响应为空 |
| 连接与断线 | 连接超时、登录时断线后重连/迟到成功不能改为通过 |
| 资金查询 | 空结果正常结束、多条记录等待最后一条、错误编号、业务失败、断线 |
| 行情登录 | 业务失败、错误编号、必需响应为空 |

失败和错误编号场景确认不会错误推进后续请求。查询没有记录会明确显示空结果；不会编造资金行。假后端的成功只代表程序正确处理了模拟响应，不是柜台成功凭证。

## Windows 实体机待执行

1. `build_windows.bat` 成功生成 x64 EXE 并复制配套 DLL。
2. `run_windows.bat --version` 记录实际加载的两套 API 版本。
3. 以管理员身份运行 `run_windows.bat --mode trader`，确认前置、认证、登录、资金查询各步结果。
4. 运行 `run_windows.bat --mode md`，单独核验行情前置和登录。
5. 保存真实账号登录截图及日志；登录当天及时通知中信核验终端信息。

此阶段还没有正式图文手册、实测截图、录屏、交易成交或风控通过证据，也没有病毒检测结果。后续项目见 `REPORT_ROADMAP.md`。
