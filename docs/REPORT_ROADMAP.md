# 附件六测试路线图与证据清单

本文件依据用户提供的《附件六：信息系统股票期权接入测试报告模板》和本次补充的八项检查要求编写。用于分阶段开发和收集证据，**不是已经通过的测试报告**。

当前版本除连接、交易端认证及登录、只读查询和行情端登录外，已实现一个受显式确认保护的基础功能测试：报单数量固定为 1 的单次 GFD 限价委托，进入排队后自动撤单。维护端尚未在 Windows 评测柜台实发，用户也尚未提供两所当日有效测试合约和价格，因此当前只有代码与离线状态机验证，不能据此勾选两所基础功能实测通过、完整风控或穿透式监管通过。

## 1. 当前阶段要证明什么

| 编号 | 本阶段检查 | 成功依据 | 不能由此得出的结论 |
| --- | --- | --- | --- |
| C01 | 交易前置连接 | 收到交易 API 的 `OnFrontConnected` | 不能说明账户已登录或认证码有效 |
| C02 | 交易端客户端认证 | 对应 `ReqAuthenticate` 的认证响应明确成功 | 不能说明交易账户已登录 |
| C03 | 交易账户登录 | 对应登录请求的 `OnRspUserLogin` 响应明确成功，并记录账户、登录时间、交易日等可用信息 | 不能说明已成交或监管终端信息已通过后台核验 |
| C04 | 交易端只读查询 | 查询请求得到对应正常响应，并收到最后一条响应；具体查询项目见运行说明 | 查询无数据不等于 API 不通；查询成功不等于具备下单权限 |
| C05 | 行情前置连接及登录 | 行情 API 收到连接回调，并收到对应成功登录响应 | 不能说明已订阅合约或已经收到实时行情 |
| C06 | 失败定位 | 区分连接、认证、登录、查询阶段；保存错误码、时间和超时位置 | 请求函数返回 `0` 仅表示提交被接受，不能替代异步业务成功响应 |

上述项目都需要在实际运行后记录“成功 / 失败 / 未执行”。交付代码、编译成功或离线验证不能代替账户登录测试，也不能填入虚构的成功截图。

## 2. 与附件六正文逐项对应

| 附件六栏目 | 当前阶段能够准备的内容 | 后续完成条件 |
| --- | --- | --- |
| 系统说明 | 说明软件用途、直连接入模式、API 版本、当前只读连接范围 | 最终报告改为最终提交版本的真实系统说明 |
| 功能介绍 | 交易连接、客户端认证、交易登录、只读查询、行情登录、错误日志；单次限价报单/撤单测试策略 | 后续功能按实际实现补充；不能把单次策略描述成行情选价、追价或完整交易系统 |
| 测试基础信息 | 软件名称与版本、测试账号、测试时间、APPID、实际终端内网 IP、MAC、测试环境 | 使用实际测试机与实际会话的信息；中继字段依接入方式填写 |
| 穿透式监管 | 记录原生 API、实体终端、管理员运行、登录及设备信息核验线索 | 当天请券商后台确认采集、上报和账号对应信息；登录成功本身不是完整通过证据 |
| 基础功能：程序化交易下单、交易策略、其他 | 已实现 `single-shot-limit`：`VolumeTotalOriginal=1` 的单次限价委托，排队后自动撤单；默认 dry-run | 分别使用两所真实测试合约实发，取得委托/撤单回调、截图、录屏及券商当天后台核验 |
| 风控：单日最大报单限制 | 当前未实现；报备表阈值尚未提供 | 阈值与报备表一致，并提供设置截图和触发提示截图 |
| 风控：每秒最大报单数限制 | 当前未实现；报备表阈值尚未提供 | 阈值与报备表一致，并提供设置截图和运行截图 |
| 风控：异常价格检查 | 当前未实现 | 实现并验证拦截或提示逻辑，提供异常提示截图及录屏 |
| 客户端是否具有分仓或再次外接功能 | 当前连接工具不实现此功能 | 最终软件确实没有时注明“不使用 / 无”；最终增加时必须补充相应测试 |
| 测试截图：登录 | 在实体机实际成功后截图，截图包含账号信息 | 与测试日期、软件版本和录屏对应；密码及授权码不应出现在截图中 |
| 测试截图：基础功能 | dry-run 不能作为柜台报单通过截图；实发结果待用户执行 | 截取合约、交易所、策略参数、委托状态及撤单结果；发生成交时如实记录 |
| 测试截图：风控功能 | 当前标记“未执行”，不能生成模拟截图替代 | 覆盖单日、每秒及价格异常测试，保留触发前后状态 |
| 测试截图：分仓或再次外接功能 | 无此功能时按模板注明 | 以最终软件情况为准 |
| 软件文件目录 | 可提供最终执行程序目录的结构 | 截图应为实际交付版本目录，能看出执行程序和必要依赖 |
| 软件压缩包 / 安装包的 MD5 | 可对当前阶段包做版本识别 | 正式提交时必须重新计算最终压缩包或安装包的 MD5，并备份同一文件 |
| 软件安全 | 当前不能宣称已通过病毒检测 | 对最终提交的压缩包或安装包执行病毒检测，并保存工具、日期与结果证据 |
| 盖章 / 个人签字、日期 | 保留待填写 | 报告及证据核对完成后由申请人办理，不生成或代签 |

模板要求“实现了打 ☑，未实现打 □”，并要求测试软件与实盘软件一致。当前阶段勾选应与实际实现相符；最终报备版本中已经列入测试范围的功能都必须有实现和验证，不能靠删减截图代替。

## 3. 分阶段推进

### 阶段一：实体机连接和登录

1. 在用户实际用于测试的 Windows 实体机上准备匹配架构的评测版 API，管理员权限运行程序；使用券商给出的个股期权评测环境。
2. 分别运行交易端和行情端连接测试，定位连接、认证、登录、查询是否成功。
3. 保存实际软件版本、API 版本、测试日期、时区、时间段、交易日和原始结果日志。
4. 登录成功后当天及时告知券商，请其核验测试账号、APPID 及终端采集信息。根据用户说明，后台只能查询当天记录，不能留待次日再核验。
5. 报告登录截图需要包含账号信息；录像覆盖从启动程序到登录结果的过程，录制时避免把密码或授权码展示出来。

本阶段不以交易所成交、行情订阅或风控完成为验收条件。

### 阶段二：基础交易能力

1. 已增加明确可控的单次报单/撤单策略；下一步补充委托查询、成交与持仓展示，并按最终申报范围完善策略说明。
2. 确认账户在上交所、深交所的可用测试权限、合约及测试时段后，分别完成交易验证，保存交易所、合约、委托及成交证据。只查到两个交易所的合约不等于完成两个交易所的交易。
3. 按用户检查要求，登录和交易当天及时告知券商，提供准确时间段；由券商核验后台记录。不能把程序自行输出的“成功”当作券商后台已确认。
4. 根据最终软件实际功能完善基础功能截图及完整功能演示录屏。

### 阶段三：三项风控

两个数量阈值目前均未知，必须从正式报备表取得，不能随意填写演示值作为申报值。

| 风控 | 必须确定的口径 | 报告证据 |
| --- | --- | --- |
| 每日最大报单量 | 正式数值；按账号还是程序累计；撤单、失败请求是否计数；交易日切换和重启后的计数行为 | 设置截图清楚显示与报备表一致的阈值；触发截图显示阈值、当前计数和被阻止的动作 |
| 每秒最大报单量 | 正式数值；固定时间窗还是滑动窗口；作用范围；超限请求的处理方式 | 设置截图清楚显示正式阈值；运行截图显示时间窗、实际计数及限流结果 |
| 价格异常 | 使用的价格边界、偏离参考价规则或其他实际申报规则；无有效参考行情时的行为 | 价格异常提示截图，展示输入、检查依据及处理结果；同时录屏 |

测试用例需要覆盖阈值内、达到阈值和超出阈值的行为。程序应清楚显示拒绝原因，避免只有后台日志而用户看不到提示。内部开发可以使用较小阈值快速验证，但正式截图必须来自与报备表一致的正式设置及对应运行过程，不得修改截图数字。

### 阶段四：证据和提交包

1. 录制程序功能演示，覆盖报告中每个需要截图的功能点，包括登录、基础功能及风控；价格异常需要对应录像。
2. 编写图文使用手册，至少覆盖报告测试点：环境准备、管理员启动、登录、行情与交易功能、风控设置、触发提示、日志和故障处理。
3. 固定交付版本，记录软件版本与 API 版本，整理实际执行目录，打出程序压缩包或安装包并备份。
4. 对该最终文件计算 MD5，保存文件名、大小、MD5 和计算时间；可以同时保留 SHA-256。任何重打包都会产生新的待核对文件，必须重新计算。
5. 对同一最终包执行病毒检测，保存检测工具名称、检测日期和结果。MD5 只能帮助确认文件一致性，不能证明软件无病毒。
6. 将真实截图、录像、手册、最终包及校验记录逐项对应到附件六，再办理盖章或签字。

## 4. 终端采集与原生 API 的边界

本项目使用用户提供的个股期权原生 SDK。不要仅凭 `OnRspUserLogin` 成功就写“穿透式监管已通过”，也不要因为能列出本机网卡信息就认为券商后台已经收到完整终端信息。

附件 SDK 的登录结构 `CThostFtdcReqUserLoginField` 存在 `MacAddress`、`ClientIPAddress`、`ClientIPPort` 等字段；这些字段的存在并不证明当前运行中实际完成了什么采集。报告需要本机内网 IP 和 MAC 时，应核对真实测试终端及实际使用的网卡，不能随意选择 VPN、虚拟网卡或容器网卡信息填报，也不能填写预设或伪造设备信息。

附件交易 API 头文件将 `RegisterUserSystemInfo` 注释为“中继服务器多连接模式”，将 `SubmitUserSystemInfo` 注释为“中继服务器操作员登录模式”。本次业务信息为直连接入，因此不能为了出现一个“上报成功”的日志就照搬中继接口调用；也不能伪造采集数据填充接口。

原生 API 是否已经按该版本要求完整采集，以及后台看到的终端标识是否正确，需要结合供应商对该评测包的说明和券商当天后台核验确认。实体机、管理员权限、正确评测 API 与正确环境是本次检查要求的一部分。开发环境中的编译或离线测试不能替代这项验证。

直连报告中的 `RELAYAPPID` 与中继代理公网 IP 可按模板注明“不适用（直连）”；若以后接入方式改成中继，必须重新核对接口流程与报告信息。

## 5. 建议保留的证据记录

每次正式测试建立独立记录，内容至少包括：

- 软件名称、版本、API 版本、最终可执行文件或程序包识别信息。
- 测试日期与时区、开始结束时间、交易日、测试账号和 APPID。
- 实际环境、终端内网 IP、MAC、实体机与管理员运行情况。
- 本次执行的测试编号、步骤、预期结果、实际结果和证据文件名。
- 与报备表一致的正式阈值；来源报备表的版本或日期。
- 当天通知券商的时间以及后台核验结论；未核验时写“待核验”。

原始日志、截图和录像以实际执行为准。测试失败也应保留真实结果，修复后另存新的测试记录；不要覆盖失败记录或将未执行的项目写成通过。
